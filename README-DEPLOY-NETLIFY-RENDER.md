# T-CARE — Free deployment (Netlify + Render + existing Supabase)

This deployment keeps the existing Express API intact to minimize deployment changes.

## Services
- Netlify Free: React/Vite frontend (`npm ci && npm run build`, publish `dist`).
- Render Free: Express backend (`backend` root, `npm ci && npx prisma generate`, start `npm start`).
- Existing Supabase: PostgreSQL and private Storage. Do not create a replacement database.
- Brevo Free: OTP transactional email over HTTPS API (300 emails/day; verify sender first).

## 1. Push this project to GitHub
Commit the project root, including `netlify.toml`, `render.yaml`, `.node-version`, and `public/_redirects`. Never commit `.env` files or secrets.

## 2. Deploy backend on Render
Create a Web Service from the repository. Set Root Directory to `backend`; Render can use `render.yaml` if Blueprint deployment is selected. Choose the Free instance. The build/start/health-check settings are in `render.yaml`.

Set these environment variables in Render (Dashboard → service → Environment):
- `DATABASE_URL`: existing Supabase PostgreSQL connection string; use the recommended Supavisor pooler connection string for runtime.
- `SUPABASE_URL`: existing project URL.
- `SUPABASE_SECRET_KEY`: server-only Supabase secret key.
- `SUPABASE_STORAGE_BUCKET`: exact existing private bucket name (default in template: `tcare-media`).
- `FRONTEND_ORIGIN`: exact Netlify production URL, with no trailing slash. Initially use the future Netlify URL and correct it after step 3.
- `BREVO_API_KEY`: Brevo API key.
- `EMAIL_FROM_EMAIL`: sender address verified in Brevo.

`JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` are generated by the Render Blueprint. If creating the service manually, set two different random values, each at least 32 characters.

Render Free sleeps after 15 minutes of inactivity and can take about a minute to wake. Its filesystem is ephemeral; T-CARE uses Supabase for durable data/files. Render Free blocks SMTP ports, so production OTP delivery uses Brevo's HTTPS API rather than Gmail SMTP.

## 3. Deploy frontend on Netlify
Import the same GitHub repository in Netlify. Build settings are in `netlify.toml`:
- Build command: `npm ci && npm run build`
- Publish directory: `dist`
- Environment variable: `VITE_API_BASE_URL=https://YOUR-RENDER-SERVICE.onrender.com`

Deploy, then copy the exact Netlify production URL.

## 4. Finalize backend CORS
In Render, set `FRONTEND_ORIGIN` to the exact Netlify production URL (no trailing slash), then redeploy the backend.

## 5. Database safety
The current audited package contains four migrations. Before applying any migration, inspect the Supabase migration status and confirm which migrations have already been applied. Never run `prisma migrate reset`. Do not run `migrate deploy` blindly against an existing database. The KYC and cancellation migrations may already have been applied by the project owner; verify first.

## 6. Smoke tests
1. `https://YOUR-RENDER-SERVICE.onrender.com/api/v1/health`
2. Open Netlify site; hard-refresh nested routes (SPA redirect).
3. Register Customer and Gardener; verify OTP arrives.
4. Login/logout/session refresh; test role protection.
5. Customer plants/addresses → booking → Admin assignment → Gardener execution → completion.
6. Verify private Storage upload/download/delete and unauthorized access denial.
7. Test KYC, notifications, reviews/issues, CMS, and Admin analytics.

## Free-tier guardrails
- Do not add a payment method to Render if you want to prevent accidental usage charges; without one, usage limits suspend service instead of charging.
- Netlify Free has a 300-credit monthly hard limit; projects pause at the limit.
- Brevo Free allows 300 email sends/day and includes Brevo branding.
- Render Free backend cold-starts after inactivity. This is acceptable for a low-traffic preview, not a production uptime guarantee.
