# T-CARE Backend — Dependencies and Setup Required

## npm dependencies
The backend already declares:
- `@prisma/client`
- `prisma` (development dependency)
- `bcrypt`
- `cookie-parser`
- `cors`
- `dotenv`
- `express`
- `jsonwebtoken`
- `nodemailer`
- `zod`

The `deepmerge-ts` override is pinned to `8.0.2` under `@prisma/config` to avoid the previously observed advisory without upgrading Prisma major versions.

After extracting the clean ZIP, run in `backend/`:
```bash
npm ci
npx prisma generate
npx prisma validate
npx prisma migrate status
```

Apply any pending migration with `npx prisma migrate deploy`; do not use `migrate dev` against the hosted Supabase project.

## Infrastructure configuration required
- Supabase PostgreSQL `DATABASE_URL`
- Supabase project URL
- Supabase Secret API key (`SUPABASE_SECRET_KEY`, server only)
- Private `tcare-media` Storage bucket
- JWT access/refresh secrets
- frontend origin
- Gmail SMTP sender settings and App Password
- Admin provisioning values (email; name defaults to T-CARE Administrator; initial password can be generated by CLI)
- Payment provider credentials are present in the template but excluded from the current non-payment implementation/verification scope.

## Authentication / Gmail setup additions

- Nodemailer is included in backend dependencies.
- Configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, and optional `SMTP_FROM`.
- Use a dedicated T-CARE sender Gmail account with Google 2-Step Verification and an App Password.
- Run `npm run email:verify` after configuring sender credentials.
- Configure `ADMIN_EMAIL`, `ADMIN_FULL_NAME`, and `ADMIN_INITIAL_PASSWORD` and run `npm run admin:provision` once to create the separate verified Admin identity.
- Public registration must accept only `CUSTOMER` and `GARDENER`; Admin is provisioned by CLI.
- Existing accounts with `emailVerifiedAt = null` must use the resend + verify flow before login.
